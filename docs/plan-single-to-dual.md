# План развития проекта: single core → dual core

Проект: yoRadio (форк) — ESP32-S3 (Wrover) + PCM5102, I2S-дуплекс, BT-источник через Wrover.
Дата плана: 22.11.2026.

---

## Исходное положение

- **git_yoRadio_Wrover_S3** (single core) — текущий проект. Железо меняться не будет,
  проект подходит к финалу. Уже сделано: I2S-дуплекс (этапы 1–3а), RX-счётчик
  подтверждён в боевой прошивке, радио играет без деградации.
- **git_yoRadio_Wrover_S3_Dual_Core** — новый проект, полностью наследует single core
  и развивается дальше на расширенном железе (2 процессора, BT-плечо на Wrover).
- Хочется: в single core добавить выбор источника звука (SD / WiFi-радио) — как в
  jradio (https://github.com/jmper-ha/jradio) — и этим закрыть проект. Затем перенести
  дополнение в dual core и расширить третьим источником — Bluetooth.

## Главный принцип

Не вести два репозитория параллельно, а выстроить конвейер:
**закрыть single core релизом → перенести весь пласт в dual core → развивать там.**

Даже на финальном этапе single core писать фичу в переносимом виде:
- вынести выбор источника в отдельный модуль (например, `src/core/audiosrc.h/.cpp`);
- enum источников, функции `audiosrc_begin()`, `audiosrc_stop()`, сохранение
  выбора в конфиг;
- страница/пункт меню вызывает только этот модуль, логика плеера не вплетается
  в код экрана;
- тогда в dual core добавление BT = один новый элемент enum + ветка в `begin/stop`.

У jradio тот же принцип: источник — пункт меню, выбор открывает экран плеера
конкретного источника, каждый источник самодостаточен.

## Порядок работ

### Шаг 1. Single core — финальный функциональный рывок
- Добавить страницу/пункт меню выбора источника: «Радио / SD-карта».
- Механика: пункт в главном меню, значение сохраняется в конфиг, переключение =
  корректный stop() текущего потока + запуск нового.
- Если в форке живёт SD-плеер из yoRadio — опираться на него.
  Если нет: Flash/RNG/декодер уже есть в стеке yoRadio, добавится только навигация
  по файлам. Тогда сузить рамку: «выбор источника SD» = воспроизведение по кнопке,
  без файлового браузера.

### Шаг 2. Стабилизация и релиз
- Прогнать стандартные сценарии: радио, переключение станций, SD, ИК-пульт,
  громкость.
- Снять финальный тег:

      git tag -a v3.0.0 -m "final release: wifi radio + SD source selection, I2S duplex ready"
      git push origin main --tags

- В README: «Проект завершён, финальный релиз v3.0.0; дальнейшее развитие —
  в git_yoRadio_Wrover_S3_Dual_Core».
- Это важно: через полгода не вспомнить, какой форк «живой» — README это фиксирует.

### Шаг 3. Перенос в dual core — сразу, не откладывать
Нюанс: правки этапов 1–3 (RX-режим, DIN8/IR18, rxDebugLoop) сделаны в single core,
а их место — в dual core: BT-плечо дуплексной архитектуры живёт именно там.

- Финализировать single core (шаги 1–2).
- Перенести последний хвост коммитов single core целиком (дуплекс + выбор
  источника) в dual core: `git merge`, cherry-pick по хешам или patch-файлом —
  смотря как расходились ветки.
- Убедиться, что dual core собирается и радио играет — это база отрыва.
- Дальше все новые этапы (3б, BT-источник, Wrover) — только в dual core.

### Шаг 4. Single core после релиза
- Заморозка: правки — только критические багфиксы (по желанию — ветка maintenance).
- Репозиторий остаётся исторической опорой и точкой «это точно работает
  на этом железе».

## Почему такой порядок, а не «сначала всё в dual core»

- Дуплексные правки малы (десяток строк), но rxDebugLoop и готовность слейв-RX —
  фундамент BT-источника: без них следующий этап в dual core не начнётся.
- Переносить их ДО выбора источника — получить в dual core полуживую базу,
  к которой фича всё равно добавится потом.
- Финальный тег single core, снятый ПОСЛЕ добавления источника, — контрольная
  точка: «последнее состояние однопроцессорного железа, проверенное». Если в
  dual core что-то поедет — есть репер для сравнения.
- Смена версии (v2.0.0 → v3.0.0) отражает смену статуса: не «очередное изменение»,
  а «финиш линии».

## Что дальше в dual core (контекст планирования)

1. Перенос базы (шаг 3).
2. Этап 3б — Wrover в роли I2S-слейва-TX (план Б): скелет на библиотеке
   pschatzmann/ESP32-A2DP, режим I2S_MODE_SLAVE | I2S_MODE_TX.
   Схема: S3 — мастер (BCLK GPIO38, LRC GPIO39), Wrover выдаёт поток на DIN (GPIO8).
   Обмен пинами: DIN 17→8, ИК 8→18 (сделан в single core, перенесётся).
3. Интеграция BT-потока в воспроизведение: третий источник SRC_BT читает RX-плечо
   (слейв-RX) и подаёт данные в тракт. Здесь окупается дуплексная подготовка
   этапов 1–3.
4. Возможно, позже: форк jradio-bt для полноценного BT (метаданные, управление,
   передача на колонку) — кандидат на этап 4+, если BT нужен расширенный.
